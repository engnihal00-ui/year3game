Teacher worked example
1. Start when the green flag is clicked. 2. Move forward 100. 3. Turn right 90. 4. Move forward 100. 5. Say "I made it!" 6. Stop.
Say aloud: "Decomposition = breaking a big problem into smaller, easier steps. My algorithm must be clear, ordered and complete."

Debug challenge

Bug 1: Missing step
when green flag clicked
move (100) steps
move (100) steps
say [I made it!] for (2) seconds
stop all
Problem: the sprite does not turn.
Fix: add turn ↻ (90) degrees between the two moves.
Bug 2: Wrong order
when green flag clicked
say [I made it!] for (2) seconds
move (100) steps
turn ↻ (90) degrees
move (100) steps
stop all
Problem: the sprite says "I made it!" before it gets there.
Fix: move the say block to just before stop all.
Extension Bug 3 (fast finishers): Two bugs
move (100) steps
turn ↻ (90) degrees
say [I made it!] for (2) seconds
move (100) steps
stop all
Problems: no green flag block, and the say block is too early.
Fix: add when green flag clicked on top. Move say to the end.
Sentence starters: "The bug is in step ___ because…" · "I fixed it by…" · "The corrected order works because…"
Process: 1) Run it. 2) What is wrong? 3) Which step is missing or in the wrong place? 4) Fix it. 5) Run it again.

Teacher guide

Questions while circulating
  1. What are the smaller steps?
  2. Why does this block come next?
  3. What would happen if we swapped these two steps?
  4. Which block matches step 3 on your plan?
  5. Is your algorithm complete? What is missing?
  6. How do you know your steps are in the right order?
  7. What did your partner find that you did not?
  8. How did you find the bug?
  9. Why does the corrected order work?
  10. Could a robot follow your steps exactly?
Look for: a clear start, ordered steps, no missing step, blocks that match the plan.
Common mistakes and quick fixes
MistakeQuick fix
Blocks not snapped togetherDrag one block near another until it clicks.
No green flag hat blockAdd the Events block on top.
Sprite turns the wrong wayTry ↺ instead, or change the number.
Too many actions in one blockSplit into smaller blocks. Match one block to one step.
Sprite moves too fast to seeAdd wait (1) seconds between steps.
Troubleshooting: Sprite off the Stage → click the sprite, go to x: 0 y: 0. Project will not run → click the green flag on the Stage, not the script area. Script will not start → check the hat block is on top. Sprite lost → click "Sprites" list to select it.
Safety: Save with the agreed class name. No personal information in project names or messages.

Differentiation

🤝 Support
  • Picture sequence of the journey.
  • Pre-selected sprite.
  • Partially built script (green flag + first move), learners add the rest.
  • Small set of action blocks only: move, turn, say, stop.
  • Rehearse the steps aloud before coding. Work with a supportive partner.
🚀 Extension (Gifted and Talented)
  • Create a longer journey of 7–10 ordered steps.
  • Add one deliberate bug. Challenge a partner to find and fix it.
  • Explain why the corrected order works.

Assessment and plenary

My checklist
What comes next? (teacher says part of the algorithm)
